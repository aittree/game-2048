## 1. 设计目标

1. **规则可测**：棋盘的滑动、合并、生成、胜负判定做成纯数据模型，不 import pygame，用 pytest 就能覆盖。
2. **表现可换**：渲染层只读取模型快照，不反向修改模型；将来替换成 pyglet / Tkinter / Web 时模型不动。
3. **打包无损**：同一份代码既能 `python main.py` 跑，也能打成单文件 exe 跑，不需要维护两份资源路径逻辑。
4. **规模克制**：单人开发、约 1700 行（含测试与注释）完成，不过度抽象；不引入 ECS、事件总线等重架构。

## 2. 总体架构

采用**简化三层架构**（Model–Controller–View 的裁剪版）：模型层、应用层、表现层，依赖方向严格单向向下。

```
┌────────────────────────────────────────────────────────┐
│  表现层 Presentation            src/ui/                │
│  ┌──────────┐  ┌──────────┐  ┌─────────────┐           │
│  │ theme.py │  │renderer  │  │ animator    │           │
│  │ 配色字号  │  │ 绘制棋盘  │  │ 滑动/弹出动画│          │
│  └──────────┘  └──────────┘  └─────────────┘           │
│        ▲ 只读模型快照，只绘制，不改数据                  │
└────────┼───────────────────────────────────────────────┘
         │
┌────────┼───────────────────────────────────────────────┐
│  应用层 Application           game.py / main.py        │
│  ┌────────────────────────────────────────────┐        │
│  │  Game: 状态机 + 输入分发 + 事件循环协调      │        │
│  └────────────────────────────────────────────┘        │
│        ▲ 调用模型接口           │ 读取存档 / 写入存档    │
└────────┼───────────────────────┼────────────────────────┘
         │                       │
┌────────┼───────────────────────┼────────────────────────┐
│  模型层 Model                 │     基础设施 Infra      │
│  ┌───────────────────┐  ┌─────┴──────┐ ┌─────────────┐ │
│  │ board.py          │  │ storage.py │ │ resource.py │ │
│  │ 棋盘/合并/判定     │  │ 设置/排行榜/│ │ 资源路径解析 │ │
│  │                    │  │ 最高分持久化│ │              │ │
│  └───────────────────┘  └────────────┘ └─────────────┘ │
│  ┌───────────────────┐                                 │
│  │ config.py         │  常量：尺寸、概率、路径、版本     │
│  └───────────────────┘                                 │
└────────────────────────────────────────────────────────┘
```

**分层依赖规则**（作为 Code Review 的硬性检查项）：

| 模块 | 允许依赖 | 禁止依赖 |
| --- | --- | --- |
| `board.py` | 标准库（random） | pygame、ui、game、storage |
| `config.py` | 标准库 | 其他业务模块 |
| `storage.py` / `resource.py` | 标准库 | pygame、ui |
| `game.py` | board、config | pygame、storage（落盘统一由 main 负责） |
| `ui/*` | pygame、config、board 的快照结构 | 修改 board / game 内部状态 |
| `main.py` | 全部 | — |

## 3. 模块划分

| 模块 | 职责 | 对外主要接口 |
| --- | --- | --- |
| `main.py` | 初始化 pygame、窗口、字体，驱动「菜单 / 游戏 / 设置 / 排行榜 / 昵称输入」界面状态机与主循环 | `main()` |
| `config.py` | 窗口/棋盘尺寸、颜色表、生成概率、动画时长、昵称长度、应用名与版本 | 常量与 `APP_NAME`、`APP_ID`、`VERSION` |
| `board.py` | 棋盘数据；四方向移动与合并；随机生成；胜/负判定 | `Board.move(dir) -> MoveResult`、`Board.spawn()`、`Board.is_game_over()`、`Board.has_value(2048)`、`Board.clone()` |
| `game.py` | 一局游戏的完整状态：分数、最高分、状态（RUNNING/WIN/GAME_OVER）、撤销栈；把外部「按键动作」翻译成模型调用并广播渲染事件 | `Game.handle_action(action)`、`Game.reset()`、`Game.snapshot()` |
| `storage.py` | 读写 `save.json`：最高分、显示设置、排行榜前 10；容错与原子写入 | `load_profile()`、`save_profile(profile)`、`qualifies(profile, score)`、`insert_record(profile, name, score)` |
| `resource.py` | 统一资源定位：源码运行走相对工程根，exe 运行走 `sys._MEIPASS` | `resource_path(*parts) -> str` |
| `ui/theme.py` | 数值→配色、位数→字号、布局坐标计算 | `tile_color(v)`、`text_color(v)`、`font_size(v)`、`cell_rect(r, c)` 及菜单/设置/排行榜/输入框等布局常量 |
| `ui/renderer.py` | 每帧绘制棋盘与各界面；按钮点击检测 | `Renderer.draw(...)`、`draw_menu`、`draw_settings`、`draw_leaderboard`、`draw_name_entry`、`draw_dialog`、`hit_*` |
| `ui/animator.py` | 维护进行中的动画（滑动位移、合并缩放、新块弹出） | `Animator.start(result, new_pos)`、`Animator.update(dt)`、`Animator.active` |

## 4. 目录结构

见 `README.md` 第三节，此处不再重复；关键约定：

- `src/` 为可导入包，`main.py` 放在工程根，`python main.py` 与 PyInstaller 入口一致。
- `assets/` 存放**必须随 exe 分发**的二进制资源（图标、字体）；代码中的图片/字体一律通过 `resource_path()` 定位。
- `tests/` 只测模型层，不依赖 pygame，可在 CI 中无头运行。

## 5. 运行时模型

- **单线程 + 单主循环**：`while running: 处理事件 → 更新动画 → 绘制 → `clock.tick(60)`。不引入线程，避免与 pygame 事件队列竞争。
- **帧率**：60 FPS 上限；动画基于 `dt`（毫秒增量）推进，掉帧不影响动画时长。
- **输入模型**：pygame 的 `KEYDOWN` 事件在 `main.py` 被翻译为抽象动作枚举（`UP/DOWN/LEFT/RIGHT/RESTART/UNDO/CONTINUE`），再交给 `Game.handle_action()`。这样 `game.py` 与 pygame 解耦。
- **输入节流**：动画播放期间的方向键只缓冲最近一手，动画结束后立即执行；重开/撤销/继续挑战则立即生效并终止动画，避免方块瞬移。
- **长按处理**：使用 `pygame.key.set_repeat(120, 60)`；不自己写计时器。
- **状态机**：

```
        ┌──────────┐  出现 2048 方块    ┌──────────┐
        │ RUNNING  ├──────────────────►│   WIN    │
        │ 可操作    │                    │ 弹通关浮层│
        └────┬─────┘◄───────────────────┴────┬─────┘
             │ 选择「继续挑战」                │ 选择「重开」
             │ 死局                            ▼
             ▼                          ┌──────────┐
        ┌──────────┐     按 R / 再来一局  │  (重置)  │
        │ GAME_OVER│────────────────────►└──────────┘
        └──────────┘
```

- WIN 状态下棋盘**暂停接受方向键**，必须先选择「继续挑战」或「重开」，避免浮层期间后台继续变化。

## 6. 关键数据流

### 6.1 一次按键的完整链路

```
KEYDOWN(LEFT)
  → main.py 映射为 Action.LEFT
  → Game.handle_action(LEFT)
      ├─ 状态检查（WIN/GAME_OVER 时忽略方向键）
      ├─ 保存撤销快照（仅保留最近 1 步，P2 功能）
      ├─ MoveResult r = board.move(LEFT)        # 纯计算
      ├─ if not r.changed: return               # 无效移动，直接返回
      ├─ score += r.gained; 更新 best
      ├─ board.spawn() → 记录新块坐标 new_pos
      ├─ animator.start(r, new_pos)             # 表现层动画启动
      ├─ if board.has_value(2048) and not win_flagged: state = WIN
      ├─ elif board.is_game_over(): state = GAME_OVER
  → 下一帧 Renderer.draw(game.snapshot(), animator.progress)
```

要点：**移动是一次性算完的**，不是「每帧滑动一格」。棋盘数据在按键瞬间就已到达终态，动画只是在视觉上把「起始位置 → 终态位置」插值播放。这样逻辑与动画彻底解耦，掉帧也不会导致规则错误。

### 6.2 存档流

```
启动 → storage.load_profile()
  ├─ 文件不存在 / JSON 解析失败 / 字段类型不对 → 返回默认 Profile（best=0、窗口模式、空榜）
  └─ 兼容旧版只有 {"best": n} 的文件
记录变化（设置切换 / 登记成绩 / 退出确认）→ storage.save_profile(profile)
  ├─ 目录不存在 → 创建 %APPDATA%\2048Desktop
  ├─ 写临时文件 → os.replace 原子替换（避免写一半断电损坏）
  └─ 排行榜按分数降序保留前 10 条
```

### 6.3 界面状态流

```
启动 → 主菜单（开始 / 设置 / 排行榜 / 退出）
  ├─ 开始 → 游戏（reset 开局）
  ├─ 设置 → 窗口 / 全屏（即时切换并持久化）→ 返回菜单
  ├─ 排行榜 → 前 10 列表 → 返回菜单
  └─ 退出 → 退出确认 → 退出

游戏内 ESC / 窗口 × / Alt+F4 → 退出确认
  └─ 本局分数可进前 10 且未登记 → 昵称输入（Enter 保存 / ESC 跳过）→ 退出
死局浮层 → 可进前 10 时显示「登记成绩」→ 昵称输入 → 排行榜
```

界面状态（`menu/game/settings/ranking/entry/entry_exit`）只存在于 `main.py`，不进入 `Game`；弹窗（`restart/exit`）与昵称输入为模态，优先于游戏输入。`entry_exit` 表示登记完成后直接退出。

### 6.4 资源路径流

```
resource_path("assets", "fonts", "msyh.ttc")
  ├─ 若 sys.frozen 为真（exe 运行）→ os.path.join(sys._MEIPASS, "assets", "fonts", "msyh.ttc")
  └─ 否则 → os.path.join(工程根, "assets", "fonts", "msyh.ttc")
```

## 7. 关键设计决策

| 决策 | 选择 | 理由 |
| --- | --- | --- |
| 棋盘表示 | `list[list[int]]`，0 表示空 | 直观、易测、可直接打印断言；4×4 规模不需要稀疏结构 |
| 方向合并实现 | 先「压缩 → 相邻合并 → 再压缩」，四方向通过转置/翻转复用同一函数 | 一套逻辑覆盖四方向，避免写四份易错的代码 |
| 动画策略 | 逻辑先行结算 + 视觉插值 | 规则与帧率解耦，保证「按键即正确」，动画只是表现 |
| 动画技术选型 | 自己实现 rect 插值，不引入第三方库 | 单文件打包最省体积，pygame 原生 Surface 足够 |
| 数据持久化 | 单个 JSON 文件存 AppData | 无依赖、可读、体积小；不用数据库 |
| 字体 | 随包 `msyh.ttc`（微软雅黑） | exe 目标机字体不确定，自带字体避免中文方块乱码 |
| 打包形态 | onefile（首选）/ onedir（备选） | onefile 分发最简；若遇杀软误报或启动慢，切 onedir |
| 状态管理 | 显式枚举状态机 | 通关/结束浮层行为清晰，避免布尔标志组合出错 |
| 配置 | 模块级常量，不做配置文件 | 首版无用户可配置项需求，减少 IO 与出错面 |

## 8. 异常与容错设计

| 风险 | 处理策略 |
| --- | --- |
| 存档损坏 / 无权限 | 读：静默降级为默认 `Profile`（最高分 0、排行榜空、窗口模式）；写：捕获异常不中断游戏，只保留内存状态 |
| 字体文件缺失 | 回退 `pygame.font.SysFont("microsoftyahei", size)`，再回退默认字体，保证能启动 |
| 图标文件缺失 | 跳过 `set_icon`，不阻断启动 |
| 显示器过小 | 窗口固定 560×720，启动时按桌面尺寸居中（不强行缩小）；全屏时画布等比缩放到桌面分辨率并居中 |
| 打包后找不到模块 | 在 spec 中显式配置 hiddenimports，见 06 文档 |
| 高 DPI 下模糊 | 在 `pygame.init()` 之前用 ctypes 声明 DPI 感知（`SetProcessDpiAwareness(1)`），实现见 03 §6 与 06 §6.5 |
