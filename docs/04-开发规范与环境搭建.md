## 1. 开发环境

### 1.1 硬性要求

| 项 | 要求 | 说明 |
| --- | --- | --- |
| 操作系统 | Windows 10 / 11 x64 | PyInstaller 不能交叉编译，必须在 Windows 本机打包 |
| Python | **3.10 或 3.11（64 位）** | 3.12/3.13 也可运行，但部分 PyInstaller 版本对 3.13 支持较新；稳妥选 3.10/3.11 |
| pip | ≥ 23.0 | 保证能装 wheel，不用源码编译 |
| 编辑器 | VS Code / PyCharm 任选 | 需支持 pytest 与类型提示 |

> 不要使用 Microsoft Store 版 Python：其安装路径受沙盒保护，PyInstaller 与虚拟环境容易出现权限怪问题。请用 python.org 官方安装包。

### 1.2 安装 Python

1. 下载 `python-3.11.x-amd64.exe`（python.org）。
2. 安装时勾选 **Add python.exe to PATH**，可选 **Install for all users**。
3. 验证：

```powershell
python --version
pip --version
```

若提示「python 不是内部或外部命令」，重开终端；仍不行则手动把 `C:\Users\<你>\AppData\Local\Programs\Python\Python311\` 与 `...\Scripts\` 加入 PATH。

### 1.3 创建虚拟环境

工程根目录（`...\游戏\2048`）下执行：

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
```

若报「无法加载文件 Activate.ps1，因为在此系统上禁止运行脚本」，二选一：

```powershell
# 方案 A：仅为当前用户放宽策略（推荐，一次生效）
Set-ExecutionPolicy -Scope CurrentUser RemoteSigned

# 方案 B：本次会话绕过
Set-ExecutionPolicy -Scope Process Bypass
```

激活成功后提示符前会出现 `(.venv)`。退出用 `deactivate`。

### 1.4 依赖安装

`requirements.txt`（锁定可复现的版本区间）：

```text
pygame>=2.5.2,<2.7
pyinstaller>=6.3,<7
pytest>=7.4
```

安装（国内网络建议加镜像）：

```powershell
pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple
```

常用镜像备选：阿里云 `https://mirrors.aliyun.com/pypi/simple/`、腾讯云 `https://mirrors.cloud.tencent.com/pypi/simple/`。

导出当前真实版本（用于发布留档）：

```powershell
pip freeze > requirements-lock.txt
```

### 1.5 首次冒烟验证

```powershell
python -c "import pygame; print(pygame.version.ver)"
python main.py
```

应弹出 560×720 窗口，方向键可操作。若窗口一闪而过或报 SDL 错误，见第 6 节。

## 2. 工程与命名规范

### 2.1 目录约定

- 源码一律放 `src/`，入口仅 `main.py` 一个。
- 二进制资源放 `assets/`，且**只能**通过 `resource_path()` 访问。
- 测试放 `tests/`，文件名 `test_*.py`，不得 import pygame。
- 临时脚本、截图、实验代码不进仓库，放 `scratch/` 并加入 `.gitignore`。

### 2.2 命名规则

| 对象 | 规则 | 示例 |
| --- | --- | --- |
| 模块 | 小写下划线 | `board.py`、`resource.py` |
| 类 | 大驼峰 | `Board`、`GameState`、`Renderer` |
| 函数/方法 | 小写下划线，动词开头 | `handle_action`、`is_game_over` |
| 私有成员 | 单下划线前缀 | `_merge_line`、`_undo_stack` |
| 常量 | 全大写 | `CELL_PX`、`SPAWN_4_PROB` |
| 枚举成员 | 全大写 | `Direction.LEFT` |
| 布尔变量/函数 | `is_` / `has_` / `can_` 前缀 | `is_game_over`、`has_value` |

### 2.3 代码风格

- 遵循 PEP 8，单行 ≤ 100 字符，缩进 4 空格，UTF-8 无 BOM。
- 所有公开函数写类型注解；数据结构用 `dataclass` 而非裸 dict。
- 关键算法（合并、判定、资源路径）必须有中文注释说明**为什么**这么做，而不是复述代码。
- 单个函数 ≤ 80 行；超过说明职责不单一，应拆分。
- 禁止裸 `except:`；捕获要指明异常类型，并在注释里说明降级行为。
- 禁止在业务模块里写 `print` 调试；统一通过 `logging`（级别由 `config.DEBUG` 控制）。
- 格式化工具建议 `black`（line-length 100），静态检查 `ruff`：

```powershell
pip install black ruff
black --line-length 100 .
ruff check .
```

### 2.4 依赖方向的硬约束

以下规则在 Code Review 时作为**阻断项**：

1. `board.py` 不得 import `pygame`。
2. `ui/` 不得修改 `Board` / `Game` 的内部字段，只能读快照。
3. `game.py` 不得 import `pygame`，只接受 `Action` 枚举。
4. 任何位置不得出现 `"./assets/"`、`"assets/"` 形式的字面路径。
5. 任何位置不得写入 exe 所在目录（用 AppData）。

自查命令：

```powershell
Select-String -Path src\*.py,src\ui\*.py -Pattern "import pygame|assets/|assets\\"
```

## 3. 版本控制规范

`.gitignore`：

```gitignore
.venv/
__pycache__/
*.pyc
build/
dist/
*.spec.bak
scratch/
.pytest_cache/

```

> `2048.spec` 需要入库（它定义了打包如何收集资源），但 `build/`、`dist/` 不入库。

提交信息格式（Conventional Commits 精简版）：

```
feat(board): 支持四方向合并
fix(storage): 存档损坏时不再崩溃
docs(pack): 补充 onefile 启动慢的说明
test(board): 覆盖 2-2-2-2 合并用例
chore(deps): 升级 pygame 至 2.6.1
```

一次提交只做一件事；重构与功能改动分开提交。

## 4. 调试与开发辅助

### 4.1 打开调试开关

`config.py` 增加：

```python
DEBUG = False          # 发布前确认为 False
```

- `DEBUG=True` 时：打印存档路径、异常堆栈、每帧耗时；可在窗口标题显示 FPS。
- 发布构建必须为 `False`，且不输出任何控制台信息（exe 无控制台）。

### 4.2 棋盘可视化

`board.py` 提供只读的文本打印，便于对照测试：

```python
def dump(self) -> str:
    return "\n".join(
        " ".join(f"{v:4d}" if v else "   ." for v in row) for row in self.grid
    )
```

### 4.3 快速复现特定局面

测试与调试时常需固定棋盘。`Board(grid=...)` 支持直接注入，**仅用于测试**，生产代码不要构造非法局面（如开局满盘）。

### 4.4 无头测试

pytest 不依赖显示设备，因为 `board.py` 不 import pygame。若某个测试意外引入了 pygame，用：

```powershell
$env:SDL_VIDEODRIVER="dummy"
```

## 5. 开发节奏建议

按「模型先行」顺序推进，每步都可独立验证：

| 阶段 | 产出 | 验收 |
| --- | --- | --- |
| 1 | `config.py` + `board.py` + `tests/test_board.py` | 第 05 文档的单元用例全绿 |
| 2 | `storage.py` + `resource.py` | 手工构造坏 JSON 不崩 |
| 3 | `game.py` | 状态机与分数、撤销逻辑正确 |
| 4 | `ui/theme.py` + `renderer.py`（先静态，无动画） | 窗口能显示正确棋盘与分数 |
| 5 | `animator.py` | 滑动/合并动画流畅，逻辑不受影响 |
| 6 | `main.py` 完整事件循环 | 键盘、鼠标、退出全覆盖 |
| 7 | 打包 | 第 06 文档验收清单全部通过 |

每个阶段结束都应能运行、能提交。

## 6. 常见环境问题排查

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `pip install pygame` 报 `error: Microsoft Visual C++ 14.0 required` | Python 版本过旧或架构不匹配，无对应 wheel | 升级 pip：`python -m pip install -U pip`；确认 Python 为 64 位；换 3.10/3.11 官方版 |
| 运行报 `pygame.error: No available video device` | 无图形会话（远程/服务环境） | 本地桌面运行；或设 `SDL_VIDEODRIVER=dummy`（仅测试用，看不到窗口） |
| 中文显示成方块 | 未加载中文字体 | 使用 `assets/fonts/msyh.ttc`，经 `resource_path` 加载 |
| 窗口打开一闪就退 | 主循环异常退出且无控制台 | 在终端里 `python main.py` 看堆栈 |
| 高 DPI 屏窗口模糊 | Windows 缩放未声明 DPI 感知 | 打包时在 spec/manifest 中声明 DPI 感知（见 06 第 6 节） |
| `Activate.ps1` 被拒绝 | 执行策略限制 | 见 1.3 |
| 装了两份 Python，`pip` 装错位置 | PATH 指向不一致 | 用 `python -m pip install ...`，并在 venv 内操作 |
| PyInstaller 报找不到 pygame | 打包环境与运行环境不一致 | 必须在**同一 venv** 内安装依赖并打包 |
