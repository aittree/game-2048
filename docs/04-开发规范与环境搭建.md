## 1. 开发环境

### 1.1 硬性要求

| 项 | 要求 | 说明 |
| --- | --- | --- |
| 操作系统 | Windows 10 / 11 x64 | PyInstaller 不能交叉编译，必须在 Windows 本机打包 |
| Python | **3.12（64 位）** | 统一由 miniconda 的 `game` 环境提供；PyInstaller 6.x 已支持 3.12 |
| conda | miniconda（版本不限，需支持 `conda create`） | 负责解释器与依赖隔离，不额外建 venv |
| pip | ≥ 23.0 | 保证能装 wheel，不用源码编译 |
| 编辑器 | IntelliJ IDEA（Python 插件） | 项目解释器指向 conda `game`，需支持 pytest 与类型提示 |

> 环境统一由 conda 管理。不要混用系统全局 Python 与 conda base：安装依赖前先用 `where python` 确认第一条路径在 miniconda 的 `envs\game` 下，否则依赖会装错位置。

### 1.2 创建 conda 环境

本项目使用 miniconda 的 `game` 环境（Python 3.12 x64），**不使用 venv**：

```powershell
conda create -n game python=3.12 -y
conda activate game
python --version          # 应输出 Python 3.12.x
```

若提示 `conda` 不是可执行命令，先打开「Anaconda Prompt (miniconda3)」再执行；之后可 `conda init powershell` 让 PowerShell 也能直接使用。

### 1.3 IDEA 工程配置

1. `File → Project Structure → SDKs → Add SDK → Conda Environment`，选择 `game` 环境。
2. `Run → Edit Configurations → + → Python`：Script path 指向 `main.py`，Working directory 设为工程根（`games/game-2048`）。
3. 确认 IDEA 右下角显示的解释器路径包含 `envs\game` 后再运行。

> 若 IDEA 显示的是 `base` 或系统 Python，说明解释器选错：此时 `import pygame` 会报 `ModuleNotFoundError`。整个项目只用这一个解释器，不额外创建 venv。

### 1.4 依赖安装

`requirements.txt`（锁定可复现的版本区间）：

```text
pygame>=2.5.2,<2.7
pyinstaller>=6.3,<7
pytest>=7.4
```

安装（先确认已 `conda activate game`，国内网络建议加镜像）：

```powershell
python -m pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple
```

常用镜像备选：阿里云 `https://mirrors.aliyun.com/pypi/simple/`、腾讯云 `https://mirrors.cloud.tencent.com/pypi/simple/`。

导出当前真实版本（用于发布留档）：

```powershell
python -m pip freeze > requirements-lock.txt
```

### 1.5 首次冒烟验证

```powershell
python -c "import sys; print(sys.executable)"
python -c "import pygame; print(pygame.version.ver)"
python main.py
```

应弹出 560×720 窗口并进入主菜单；点「开始游戏」后方向键可操作。若窗口一闪而过或报 SDL 错误，见第 6 节。

## 2. 工程与命名规范

### 2.1 目录约定

- 源码一律放 `src/`，入口仅 `main.py` 一个。
- 二进制资源放 `assets/`，且**只能**通过 `resource_path()` 访问。
- 测试放 `tests/`，文件名 `test_*.py`，不得 import pygame。
- 临时脚本、截图、实验代码不进仓库，放 `scratch/` 并加入 `.gitignore`。
- conda 环境位于 miniconda 安装目录，不在工程内，因此工程下**不出现** `.venv/`。

### 2.2 命名规则

| 对象 | 规则 | 示例 |
| --- | --- | --- |
| 模块 | 小写下划线 | `board.py`、`resource.py` |
| 类 | 大驼峰 | `Board`、`GameState`、`Renderer` |
| 函数/方法 | 小写下划线，动词开头 | `handle_action`、`is_game_over` |
| 私有成员 | 单下划线前缀 | `_merge_line`、`_undo_stack` |
| 常量 | 全大写 | `CELL_PX`、`SPAWN_4_PROB` |
| 枚举成员 | 全大写 | `Direction.LEFT` |
| 布尔变量/函数 | `is_` / `has_` / `can_` 前缀 | `is_game_over`、`has_value` |

### 2.3 代码风格

- 遵循 PEP 8，单行 ≤ 100 字符，缩进 4 空格，UTF-8 无 BOM。
- 所有公开函数写类型注解；数据结构用 `dataclass` 而非裸 dict。
- 关键算法（合并、判定、资源路径）必须有中文注释说明**为什么**这么做，而不是复述代码。
- 单个函数尽量 ≤ 100 行；`main._run` 主循环按事件分支分段组织并加注释，允许更长。
- 禁止裸 `except:`；捕获要指明异常类型，并在注释里说明降级行为。
- 禁止在业务模块里写 `print` 调试；未捕获异常统一写入 `%APPDATA%\2048Desktop\crash.log`（`config.DEBUG` 仅作为调试标记，发布前必须为 `False`）。
- 格式化工具建议 `black`（line-length 100），静态检查 `ruff`：

```powershell
pip install black ruff
black --line-length 100 .
ruff check .
```

### 2.4 依赖方向的硬约束

以下规则在 Code Review 时作为**阻断项**：

1. `board.py` 不得 import `pygame`。
2. `ui/` 不得修改 `Board` / `Game` 的内部字段，只能读快照。
3. `game.py` 不得 import `pygame`，只接受 `Action` 枚举。
4. 任何位置不得出现 `"./assets/"`、`"assets/"` 形式的字面路径。
5. 任何位置不得写入 exe 所在目录（用 AppData）。

自查命令：

```powershell
Select-String -Path src\*.py,src\ui\*.py -Pattern "import pygame|assets/|assets\\"
```

## 4. 调试与开发辅助

### 4.1 打开调试开关

`config.py` 增加：

```python
DEBUG = False          # 发布前确认为 False
```

- `DEBUG=True` 时：打印存档路径、异常堆栈、每帧耗时；可在窗口标题显示 FPS。
- 发布构建必须为 `False`，且不输出任何控制台信息（exe 无控制台）。

### 4.2 棋盘可视化

`board.py` 提供只读的文本打印，便于对照测试：

```python
def dump(self) -> str:
    return "\n".join(
        " ".join(f"{v:4d}" if v else "   ." for v in row) for row in self.grid
    )
```

### 4.3 快速复现特定局面

测试与调试时常需固定棋盘。`Board(grid=...)` 支持直接注入，**仅用于测试**，生产代码不要构造非法局面（如开局满盘）。

### 4.4 无头测试

pytest 不依赖显示设备，因为 `board.py` 不 import pygame。若某个测试意外引入了 pygame，用：

```powershell
$env:SDL_VIDEODRIVER="dummy"
```

按「模型先行」顺序推进，每步都可独立验证：

| 阶段 | 产出 | 验收 |

## 6. 常见环境问题排查

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `pip install pygame` 报 `error: Microsoft Visual C++ 14.0 required` | Python 版本或架构不匹配，无对应 wheel | `python -m pip install -U pip`；确认 `python -V` 为 3.12 且是 64 位；在 `game` 环境内安装 |
| 运行报 `pygame.error: No available video device` | 无图形会话（远程/服务环境） | 本地桌面运行；或设 `SDL_VIDEODRIVER=dummy`（仅测试用，看不到窗口） |
| 中文显示成方块 | 未加载中文字体 | 使用 `assets/fonts/msyh.ttc`，经 `resource_path` 加载 |
| 窗口打开一闪就退 | 主循环异常退出且无控制台 | 在终端里 `python main.py` 看堆栈 |
| 高 DPI 屏窗口模糊 | Windows 缩放未声明 DPI 感知 | 在 `pygame.init()` 前调用 `SetProcessDpiAwareness(1)`（见 06 §6.5） |
| `conda` 命令不存在 / `conda activate` 无效 | PowerShell 未执行过 `conda init` | 先用「Anaconda Prompt」；或 `conda init powershell` 后重开终端 |
| 依赖装进了 base / 系统 Python | 终端未激活 `game` 环境 | `conda activate game`；`python -m pip install ...`；`where python` 第一条应在 `envs\game` 下 |
| IDEA 运行报 `ModuleNotFoundError: pygame` | 项目解释器指向 base 或系统 Python | Project Structure 中把 SDK 改为 conda `game` 环境 |
| PyInstaller 报找不到 pygame | 打包环境与运行环境不一致 | 必须在**同一个 `game` 环境**内安装依赖并打包 |
