# 06 · 打包发布指南（PyInstaller → 单文件 exe）

| 项目 | 内容 |
| --- | --- |
| 文档编号 | 2048-PKG-06 |
| 版本 | v1.0 |

| 环境 | Windows 10/11 x64 + Python 3.10/3.11 + pygame 2.5+ + PyInstaller 6.x |

本章是「代码 → 可双击分发的 exe」的完整操作规程，包含原理、配置、命令、验证与排错。

---

## 1. 打包原理（先理解再操作）

PyInstaller 不是把 Python 编译成机器码，而是把解释器、依赖包、资源打成一体：

1. `Analysis` 阶段：从 `main.py` 出发静态分析 import 链，收集 `.py`、扩展模块（`.pyd`）、DLL。
2. `PYZ`：把纯 Python 模块编译成字节码并归档。
3. `EXE`：把 bootloader + 归档 + 资源拼成 exe。
4. **运行时（onefile）**：exe 启动后把自己解包到 `%TEMP%\_MEIxxxxxx`，再以该目录为工作目录启动解释器。
5. 因此脚本内会看到两个关键事实：
   - `sys.frozen == True`（表示处于打包环境）
   - `sys._MEIPASS` 指向解包目录，**资源必须从这里找**

这解释了三个常见现象：为什么 exe 启动比脚本慢 1～2 秒、为什么资源路径要特殊处理、为什么杀毒软件容易把 onefile 报为可疑（自解压行为）。

---

## 2. 打包前置检查

在**同一个虚拟环境**内完成以下检查（打包环境必须与运行验证环境一致）：

```powershell
# 1. 确认当前 venv
python -c "import sys; print(sys.executable)"

# 2. 确认依赖齐全
python -c "import pygame; print(pygame.version.ver)"
pyinstaller --version

# 3. 确认资源存在
Test-Path assets\icon.ico, assets\icon.png, assets\fonts\msyh.ttc

# 4. 确认脚本可跑
python main.py
```

| 检查项 | 不通过的后果 |
| --- | --- |
| 在 venv 内打包 | 打包了全局环境的包，体积暴涨或版本错乱 |
| pygame 与打包同环境 | exe 启动报 `ModuleNotFoundError: pygame` |
| 图标/字体存在 | exe 无图标、运行后中文变方块 |
| `main.py` 能正常运行 | 打包出来的肯定是坏的 |

## 3. 打包形态选择

| 形态 | 命令 | 产物 | 体积 | 启动 | 适用 |
| --- | --- | --- | --- | --- | --- |
| **onefile** | `-F` | 单个 `2048.exe` | 18～30 MB | 冷启 1.5～3 s（每次解包） | 首选，分发最简 |
| **onedir** | `-D` | 一个文件夹（exe + 依赖 + assets） | 总量相近，单文件小 | 快（无需解包） | 被杀软误报、启动慢、内网部署 |

建议策略：**先出 onefile 作为交付物，同时保留 onedir 作为排障版本**。若用户反馈启动慢或杀软拦截，直接切 onedir 发文件夹压缩包。

两种形态的代码完全不用改——前提是资源路径严格走 `resource_path()`（`sys._MEIPASS` 在 onedir 下指向 `_internal` 目录，函数自动兼容）。

## 4. 命令行快速打包（首次验证用）

最短可用命令：

```powershell
pyinstaller -F -w -i assets\icon.ico --add-data "assets;assets" --name 2048 main.py
```

参数含义：

| 参数 | 作用 |
| --- | --- |
| `-F` / `--onefile` | 打成单文件 |
| `-w` / `--noconsole` / `--windowed` | 不显示命令行黑窗（GUI 程序必须加） |
| `-i` / `--icon` | exe 图标，必须是 `.ico` |
| `--add-data "源;目标"` | 把资源打进包，Windows 用**分号**分隔；目标是解包后的相对路径 |
| `--name` | 产物名 |

产物：`dist\2048.exe`。先双击验证，再改成 spec 方式做正式构建。

> 排障提示：如果 exe 一闪而过看不到错误，把 `-w` 去掉重打一次（`pyinstaller -F -i ... --name 2048_debug main.py`），运行后错误堆栈会打印在控制台。

## 5. 正式构建：spec 文件

命令行参数多且易漏，正式构建统一用 `2048.spec`（入库，作为唯一构建入口）。

### 5.1 onefile 版 spec

```python
# -*- mode: python ; coding: utf-8 -*-
# 2048.spec —— onefile 单文件构建配置
# 用法：pyinstaller 2048.spec --clean --noconfirm

block_cipher = None

datas = [
    ("assets", "assets"),          # 整个 assets 目录原样复制到包的根级 assets/
]

a = Analysis(
    ["main.py"],
    pathex=[],
    binaries=[],
    datas=datas,
    hiddenimports=[],
    hookspath=[],
    hooksconfig={},
    runtime_hooks=[],
    excludes=["tkinter", "pytest"],
    noarchive=False,
    optimize=0,
)

pyz = PYZ(a.pure)

exe = EXE(
    pyz,
    a.scripts,
    a.binaries,
    a.datas,
    [],
    name="2048",
    debug=False,
    bootloader_ignore_signals=False,
    strip=False,
    upx=False,                      # 关掉 UPX，降低杀软误报
    upx_exclude=[],
    runtime_tmpdir=None,
    console=False,                  # True 会带黑窗
    disable_windowed_traceback=False,
    argv_emulation=False,
    target_arch=None,
    codesign_identity=None,
    entitlements_file=None,
    icon=["assets/icon.ico"],
    version="version_info.txt",     # 可选，见 5.3
)
```

### 5.2 onedir 版 spec（排障/备选发布）

与上面相同，仅把 `EXE(...)` 的 `a.binaries, a.datas` 移除，并追加 `COLLECT`：

```python
exe = EXE(
    pyz, a.scripts, [],
    exclude_binaries=True,
    name="2048",
    debug=False,
    strip=False,
    upx=False,
    console=False,
    icon=["assets/icon.ico"],
    version="version_info.txt",
)

coll = COLLECT(
    exe, a.binaries, a.datas,
    strip=False,
    upx=False,
    name="2048",
)
```

产物：`dist\2048\`（含 `2048.exe`、`_internal\`、`assets\`）。分发时打包整个文件夹。

### 5.3 版本信息文件（`version_info.txt`）

让 exe 属性里显示公司、产品名、版本号，同时**降低杀软启发式误报**（无版本信息的 exe 更可疑）：

```python
VSVersionInfo(
    ffi=FixedFileInfo(
        filevers=(1, 0, 0, 0),
        prodvers=(1, 0, 0, 0),
        mask=0x3f,
        flags=0x0,
        OS=0x40004,
        fileType=0x1,
        subtype=0x0,
        date=(0, 0),
    ),
    kids=[
        StringFileInfo([
            StringTable(
                "080404b0",
                [
                    StringStruct("CompanyName", "树码科技"),
                    StringStruct("FileDescription", "2048 桌面版"),
                    StringStruct("FileVersion", "1.0.0.0"),
                    StringStruct("InternalName", "2048"),
                    StringStruct("LegalCopyright", "Copyright (C) 2026"),
                    StringStruct("OriginalFilename", "2048.exe"),
                    StringStruct("ProductName", "2048"),
                    StringStruct("ProductVersion", "1.0.0.0"),
                ],
            )
        ]),
        VarFileInfo([VarStruct("Translation", [2052, 1200])]),   # 2052 = 简体中文
    ],
)
```

改版本号时**三处同步**：`fixedfileinfo` 的两个元组、`FileVersion`、`ProductVersion`，并同步 `config.VERSION`。

## 6. 打包相关的代码要点

这些点必须在业务代码里就做对，否则 exe 一定出问题。

### 6.1 资源路径（唯一正确写法）

```python
def resource_path(*parts):
    if getattr(sys, "frozen", False):
        base = sys._MEIPASS
    else:
        base = os.path.dirname(os.path.dirname(os.path.abspath(__file__)))
    return os.path.join(base, *parts)
```

禁止写法：`open("assets/fonts/msyh.ttc")`、`pygame.image.load("icon.png")`、`os.path.join(os.getcwd(), ...)`。
onefile 下当前工作目录是**用户启动 exe 的目录**（可能是桌面、也可能是任意路径），不是 exe 所在目录，也不是解包目录。

### 6.2 字体：必须随包

- 打包 `assets/fonts/msyh.ttc`，用 `pygame.font.Font(resource_path("assets", "fonts", "msyh.ttc"), size)` 加载。
- 不要依赖 `SysFont("microsoftyahei")`：目标机器字体可能被精简版系统删除，结果全是方块。
- `msyh.ttc` 约 10～15 MB，若嫌体积大可换更轻的字体子集（仅含数字即可，因为界面文字可改为图标/英文），但会丢失中文文案，需权衡。

### 6.3 图标：exe 用 `.ico`，窗口用 `.png`

- `assets/icon.ico`：给 PyInstaller 用，需含 16/32/48/64/128/256 多尺寸（否则任务栏、属性页显示模糊或空白）。
- `assets/icon.png`（建议 64×64 或 128×128）：给 `pygame.display.set_icon()` 用。
- 原因：`pygame.image.load` 对 `.ico` 的支持依赖 SDL_image 的 ICO 解码器，在多尺寸 ico 上偶发报错或取错尺寸。用 png 最稳，代码里对图标加载要 try/except 降级。

### 6.4 存档目录：绝不写 exe 旁边

exe 可能被放在 `C:\Program Files` 或只读共享盘，写同级目录会失败（普通用户无权限，且 UAC 虚拟化行为不可控）。最高分统一写 `%APPDATA%\2048Desktop\save.json`。

### 6.5 高 DPI

打包后窗口在高缩放屏幕上可能发虚。在 `pygame.init()` 之前声明 DPI 感知：

```python
import ctypes

def enable_dpi_awareness():
    try:
        ctypes.windll.shcore.SetProcessDpiAwareness(1)   # Win8.1+
    except (AttributeError, OSError):
        try:
            ctypes.windll.user32.SetProcessDPIAware()    # Win7 兜底
        except (AttributeError, OSError):
            pass
```

调用失败不影响运行，无需处理。

### 6.6 标准输入输出与编码

`-w` 打包后 `sys.stdout` 可能为 `None`，任何 `print()` 都可能导致 `AttributeError`。发布版必须：

- 移除所有调试 `print`；
- 日志写文件而非控制台（如需日志）；
- 全局异常兜底：

```python
def main():
    try:
        _run()
    except Exception:
        import traceback
        crash_log = Path(os.environ.get("APPDATA", ".")) / "2048Desktop" / "crash.log"
        crash_log.parent.mkdir(parents=True, exist_ok=True)
        crash_log.write_text(traceback.format_exc(), encoding="utf-8")
        raise
```

有 `crash.log` 就能远程定位用户现场问题，不必让对方装 Python。

## 7. 构建与验证流程

### 7.1 标准构建命令

```powershell
# 0. 激活环境
.\.venv\Scripts\Activate.ps1

# 1. 清理旧产物（重要：避免旧的 build 缓存混入）
Remove-Item -Recurse -Force build, dist -ErrorAction SilentlyContinue

# 2. 构建
pyinstaller 2048.spec --clean --noconfirm

# 3. 看结果
Get-ChildItem dist
Get-Item dist\2048.exe | Select-Object Name, Length, LastWriteTime
```

`--clean` 清 PyInstaller 缓存，`--noconfirm` 免交互覆盖 `dist`。

构建日志重点看三处：

- `Analysis: ...` 阶段是否有 `WARNING: Hidden import ... not found`（多数无害，但涉及 pygame/SDL 的要看）。
- `ERROR:` 行——有 ERROR 基本构建失败。
- 最后 `Building EXE from EXE-00.toc completed successfully.` 才算成功。

### 7.2 本地验证（5 分钟）

```powershell
# 1. 直接运行
.\dist\2048.exe

# 2. 检查版本信息与图标
(Get-Item .\dist\2048.exe).VersionInfo | Format-List FileDescription, ProductName, FileVersion

# 3. 检查存档生成
Test-Path "$env:APPDATA\2048Desktop\save.json"

# 4. 计算哈希，登记发布记录
Get-FileHash .\dist\2048.exe -Algorithm SHA256
```

手工验证项见 05 文档第 5 节（PKG-01～08）。

### 7.3 干净机器验证

不能只在开发机验证。任选其一：

- 另一台未装 Python 的 Windows 电脑；
- 本机新建一个普通用户账户（不装 Python），在该账户下运行；
- Windows 沙盒（`Windows Sandbox`）—— 最干净，但需开启功能且无持久化。

验证重点：能启动、字体正常、能存档、能关闭无残留。

### 7.4 一键构建脚本（可选，`build.ps1`）

```powershell
$ErrorActionPreference = "Stop"
Set-Location $PSScriptRoot

if (-not (Test-Path ".\.venv\Scripts\python.exe")) {
    throw "未找到虚拟环境，请先执行 python -m venv .venv"
}

& ".\.venv\Scripts\python.exe" -m pytest -q
if ($LASTEXITCODE -ne 0) { throw "单元测试未通过，终止打包" }

& ".\.venv\Scripts\pyinstaller.exe" 2048.spec --clean --noconfirm
if ($LASTEXITCODE -ne 0) { throw "打包失败" }

$exe = Get-Item ".\dist\2048.exe"
"构建成功: $($exe.FullName)  $([math]::Round($exe.Length / 1MB, 1)) MB"
```

先跑测试再打包，避免把坏代码发出去。

## 8. 体积优化（可选）

首次 onefile 通常在 20～30 MB（pygame 的 SDL2 DLL 与字体占大头）。若需压缩：

1. **先量后减**：用 `-D` 构建 onedir，看 `dist\2048\_internal\` 里谁最大。
2. 常用 `excludes`（在 spec 的 `Analysis` 中）：

```python
excludes=[
    "tkinter", "pytest", "unittest", "pydoc", "pydoc_data",
    "test", "distutils", "setuptools", "pip",
],
```

3. **不要盲目排除** `logging`、`email`、`http`、`xml`、`asyncio` 等标准库：pygame 与 PyInstaller 运行时钩子可能间接依赖，排除后表现为启动即 `ModuleNotFoundError`。每排除一项都要重打包并跑一遍 PKG-01。
4. 字体是大头：可用 `fonttools` 做子集化（仅保留 0-9 与所需汉字），能省 8～12 MB；但子集化后一旦文案新增汉字就会显示方块，需在发版流程里把关。
5. UPX 压缩能再省 30%～50%，但**强烈不建议**用于对外分发：UPX 壳是杀软误报的重灾区。

结论：**体积不是本项目的主要矛盾**，优先保证「能跑、不误报」，20～30 MB 完全可接受。

## 9. 常见问题与排查（按现象查）

| 现象 | 根因 | 处理 |
| --- | --- | --- |
| exe 双击闪退、无任何提示 | 异常在初始化阶段抛出，`-w` 吞掉了堆栈 | 用 `--console` 重打一版看 traceback；或加 6.6 的 `crash.log` 兜底 |
| `ModuleNotFoundError: No module named 'pygame'` | 打包环境没装 pygame，或 venv 不对 | 在同一 venv 内 `pip install pygame` 后重打；必要时 spec 加 `hiddenimports=["pygame"]` |
| `ModuleNotFoundError: No module named 'pygame._sdl2'` 等子模块 | PyInstaller 钩子未收集全 | spec 中 `hiddenimports=["pygame._sdl2", "pygame.sysfont"]`；或升级 pyinstaller |
| 启动报 `FileNotFoundError: ...assets\fonts\msyh.ttc` | 资源没打进包，或路径没走 `resource_path` | 检查 `datas` 与 `sys._MEIPASS`；用 `--add-data "assets;assets"` |
| 中文全是方块/问号 | 字体未随包，或用了 SysFont | 打包 `msyh.ttc`，`pygame.font.Font(resource_path(...))` 加载，`render(..., True, color)` 开启抗锯齿 |
| 窗口无图标 / 属性页无图标 | 未传 `-i` / ico 缺尺寸 | 生成含 16～256 多尺寸 ico；spec 中 `icon=[...]` |
| `pygame.error: File is not a Windows BMP file` | 用 ico 给 `display.set_icon` | 窗口图标改用 png，ico 只给 PyInstaller |
| 启动 3～5 秒才出窗口 | onefile 每次解包到 temp | 改 onedir；或 `runtime_tmpdir` 指到固定目录减少杀软扫描；或用 splash 启动图 |
| 杀软报 `Trojan:Win32/Wacatac` 等 | 无签名 + 自解压 + 无版本信息 | 换 onedir、加 version_info、避免 UPX、提交误报、代码签名证书 |
| 高分屏字体发虚 | 未声明 DPI 感知 | 见 6.5 |
| 存档写不进去 | exe 在只读目录 / 权限不足 | 确认写 `%APPDATA%`；`save_best` 已 try/except 降级 |
| exe 体积异常大（>60MB） | 打进了全局 site-packages、conda 环境、或 assets 里有大文件 | 用干净 venv 重打；检查 `assets` 体积；查 `dist\2048\_internal` 最大项 |
| 运行提示缺 `vcruntime140.dll` / `api-ms-win-crt-*.dll` | 目标机缺 VC++ 运行库 / UCRT | 安装「Microsoft Visual C++ 2015-2022 Redistributable (x64)」，或在极精简系统上随包分发 dll |
| 32 位系统跑不了 | 用 64 位 Python 打包 | 需求只支持 x64，无需兼容 32 位 |
| 打包时 `PermissionError: dist\2048.exe` | 上一版 exe 还在运行 | 任务管理器结束 `2048.exe` 后重试 |
| 每次打包体积/内容都变 | `build/` 缓存残留 | 构建前 `Remove-Item -Recurse -Force build, dist` |

## 11. 版本与分发建议

- 版本格式 `主版本.次版本.修订号`：规则变更/新增功能升次版本，修 Bug 升修订号。
- 分发渠道：内网共享盘、网盘、企业微信/飞书群文件。分发时说明「若被浏览器/杀软拦截，请选择保留」。
- 若计划长期对外分发，建议购买代码签名证书（OV/EV），可显著降低 SmartScreen 与杀软拦截率。
- 每次发布保留一个 onedir 版本在内部归档，用于复现用户问题。
