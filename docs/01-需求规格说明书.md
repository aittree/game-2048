## 1. 引言

### 1.1 编写目的

明确 2048 桌面版的功能范围、行为细节与验收标准，作为设计、开发、测试和发布的共同依据。本文档同时可作为直播／教学场景下「从需求到可分发程序」完整链路的讲解材料。

### 1.2 项目范围

交付一个基于 Python 与 pygame 的 Windows 桌面小游戏，核心为经典 2048 玩法，最终以**单个 exe 文件**分发。不涉及联网、账号、内购、排行榜服务器等能力。

### 1.3 术语约定

| 术语 | 含义 |
| --- | --- |
| 棋盘 / Board | 4×4 的 16 个格子组成的游戏区域 |
| 方块 / Tile | 棋盘上带数字的单元，值为 2 的幂（2、4、8 … 2048 …） |
| 空格 | 值为 0 的格子 |
| 有效移动 | 执行后棋盘布局或数值发生变化的移动 |
| 无效移动 | 执行后棋盘完全不变的移动（不生成新方块、不计分） |
| 合并 | 两个相邻且等值的方块合为一个双倍值方块 |
| 通关 | 棋盘上首次出现 2048 方块 |
| 死局 | 棋盘无空格，且横纵方向均不存在可合并的相邻等值方块 |
| 最高分 | 历史单局最高得分，跨进程持久化 |

## 2. 产品概述

### 2.1 产品定位

轻量、离线、开箱即用的桌面休闲游戏。面向三类使用者：

- 普通玩家：双击 exe 即可开始，无安装步骤。
- 教学／直播演示对象：完整展示 Python 桌面开发与打包流程。
- 二次开发者：源码结构清晰，可扩展动画、主题、AI 自动玩等功能。

### 2.2 运行环境

| 项 | 要求 |
| --- | --- |
| 操作系统 | Windows 10 / Windows 11（x64） |
| 运行方式 A | 已激活 conda `game` 环境（Python 3.12）并安装依赖后执行 `python main.py` |
| 运行方式 B | 直接运行 `2048.exe`，目标机器无需 Python 环境 |
| 显示 | 最小分辨率 1024×768，窗口固定尺寸，不支持缩放 |
| 输入 | 键盘方向键 / WASD、R / U / F11 / ESC；鼠标点击按钮与菜单 |

### 2.3 用户使用场景

1. 玩家双击 exe → 窗口打开 → 进入主菜单 → 点「开始游戏」开始新的一局。
2. 游戏中用方向键操作 → 方块滑动合并 → 分数实时累加。
3. 达到 2048 → 弹出通关提示 → 可选择「继续挑战」或「重新开始」。
4. 无路可走 → 显示「游戏结束」与最终分数 → 按 R 或点击按钮重开。
5. 关闭程序再打开 → 最高分依然保留。

## 3. 功能需求

优先级定义：**P0** 必须实现（缺一不可交付）、**P1** 应实现（首版目标内）、**P2** 可选增强。

### FR-01 启动与窗口（P0）

- 程序启动后在屏幕居中打开一个固定尺寸窗口，标题为「2048」。
- 窗口图标为项目自带 `icon.png`（exe 文件图标为 `icon.ico`）。
- 启动进入主菜单，「开始游戏」后开始一局新游戏，棋盘上有 2 个初始方块。
- 以 exe 方式启动时不得出现命令行黑窗。

### FR-02 棋盘初始化（P0）

- 棋盘为 4×4，共 16 格，初始全部为空。
- 新局开始时在随机两个空格中各生成 1 个方块。
- 新方块数值规则：90% 概率为 2，10% 概率为 4。
- 随机位置不得重复，且必须落在空格上。

### FR-03 方向操作（P0）

- 支持 ↑ ↓ ← → 四个方向，同时支持 W / S / A / D 映射为 上 / 下 / 左 / 右。
- 一次按键触发一次完整移动；长按由系统按键重复控制速度，禁止出现「一次按键移动多格」。
- 移动过程中，所有方块沿方向尽可能远地滑动至边界或被其他方块阻挡。

### FR-04 合并规则（P0）

- 同一行／列中，**相邻且数值相同**的两个方块合并为一个，值为两者之和。
- 一次移动中，**每个方块最多参与一次合并**。例：一行 `[2,2,2,2]` 向左，结果为 `[4,4,0,0]`；`[4,4,8,0]` 向左结果为 `[8,8,0,0]`。
- 合并顺序从移动方向的前端开始计算（向左时从左侧开始配对）。
- 一次移动产生的多组合并得分累加，每次合并得分为合并后的数值。
- 合并后的方块在本次移动中不再参与第二次合并。

### FR-05 新方块生成（P0）

- 仅当本次移动为**有效移动**时，在移动与合并结算完成后，随机一个空格生成新方块。
- 无效移动不生成新方块、不改变分数、不触发动画。
- 若移动后棋盘已满（无空格），则不生成新方块。

### FR-06 计分与最高分（P0）

- 当前分数为本局所有合并得分之和，显示在界面上方。
- 最高分为历史各局分数的最大值，实时更新并在界面展示。
- 最高分持久化到 `%APPDATA%\2048Desktop\save.json`，程序重启后仍可读取。
- 存档文件损坏或缺失时，程序不得崩溃，按最高分 0 处理并重建文件。

### FR-07 通关判定（P0）

- 棋盘上出现数值 2048 的方块时，进入「通关」状态。
- 通关时显示祝贺浮层，提供两个选项：**继续挑战**（保留棋盘与分数，继续合成 4096、8192…）与**重新开始**。
- 通关判定只触发一次，继续挑战后不再重复弹出。

### FR-08 失败判定（P0）

- 棋盘无空格，且上下左右四个方向均不存在可合并的相邻等值方块时，判定为死局。
- 死局时显示「游戏结束」浮层，展示本局分数与最高分。
- 浮层提供「再来一局」入口，并提示快捷键 R；若本局分数可进入排行榜前 10，额外显示「登记成绩」。

### FR-09 重开与退出（P0）

- 按 R 立即重开一局，当前分数清零，最高分更新后保留。
- 点击「新游戏」按钮时先弹出确认框（「重新开始？当前进度会丢失」），确认后重开，取消则保持当前局面，避免误触丢进度。
- 关闭窗口（点击 × 或 Alt+F4）时先弹出退出确认框，确认后保存最高分并退出，不残留进程；取消则继续游戏。
- 按 ESC 同样打开退出确认框，不直接退出程序（避免误退）；已有弹窗时 ESC 等于「取消」。

### FR-10 视觉表现（P1）

- 不同数值方块使用不同底色，2 与 4 用浅色深字，≥8 用深色浅字，保证对比度。
- 方块滑动、合并、新块出现有轻量动画，单次动画时长 100～180 ms。
- 分数增加时数字有一次轻微放大反馈（可选，P2）。

### FR-11 便捷操作（P2）

- 支持鼠标点击「新游戏」按钮。
- 支持 U 键单步撤销（保留最近 1 步）。
- 支持静音开关（若后续加入音效）。

### FR-12 主菜单（P1）

- 启动后先进入主菜单，提供「开始游戏 / 设置 / 排行榜 / 退出」四个入口。
- 菜单展示当前最高分；「退出」走退出确认流程。
- F11 随时切换窗口/全屏；退出程序需二次确认（点 ×、Alt+F4 或 ESC）。

### FR-13 显示设置（P1）

- 设置页提供「窗口 / 全屏」两种显示模式，点击即时生效。
- 设置写入 `save.json`，下次启动沿用。
- 全屏采用自绘等比缩放：固定 560×720 画布缩放到桌面分辨率并居中（黑边填充，不拉伸），不依赖 SDL `SCALED` 渲染器；鼠标坐标自动映射回画布。

### FR-14 排行榜与昵称（P1）

- 排行榜保存历史最高分前 10 名，按分数降序，同分先到先得；每条记录显示名次、昵称、分数与登记日期。
- 每局游戏结束（死局）或退出（含中途退出）时，若本局分数可进入前 10 且尚未登记，可手动输入昵称登记；0 分不入榜。
- 昵称支持中英文与数字，最长 12 个字符；留空按「匿名」登记；可跳过。
- 昵称输入支持输入法提交中文（`TEXTINPUT` 事件）。

## 4. 非功能需求

| 编号 | 类别 | 要求 |
| --- | --- | --- |
| NFR-01 | 性能 | 稳定 60 FPS；按键到画面反馈延迟 < 50 ms；空闲时 CPU 占用 < 5% |
| NFR-02 | 启动性能 | 脚本启动 < 1 s；exe（onefile）冷启动 < 3 s，热启动 < 2 s |
| NFR-03 | 体积 | 单文件 exe ≤ 30 MB（含 pygame 与字体资源；字体未子集化时约 35 MB，可放宽至 40 MB） |
| NFR-04 | 可靠性 | 连续游戏 2 小时无内存持续增长；异常退出不损坏存档 |
| NFR-05 | 兼容性 | Windows 10 1809+ / Windows 11 均可运行；不依赖目标机 Python 环境 |
| NFR-06 | 独立性 | 核心逻辑模块不依赖 pygame，可在无图形环境执行单元测试 |
| NFR-07 | 可维护性 | 模块职责单一，单个函数尽量 ≤ 100 行（主循环分段例外），关键逻辑有中文注释 |
| NFR-08 | 可移植性 | 资源路径经统一解析函数处理，切换 onefile/onedir 打包方式无需改代码 |
| NFR-09 | 安全 | 不联网、不写系统目录、不请求管理员权限；存档仅写用户 AppData |
| NFR-10 | 可访问性 | 中文字体随包，避免缺字方块；数字与背景对比度 ≥ 4.5:1 |

## 5. 界面需求

### 5.1 布局

```
┌──────────────────────────────────────────┐
│  2048                分数  1024          │  ← 标题区（可选最高分）
│                      最高  20480         │
│  ┌────────────────────────────────────┐  │
│  │  4×4 棋盘（16 个圆角方块格）        │  │
│  │                                    │  │
│  └────────────────────────────────────┘  │
│  [ 新游戏 ]      方向键 / WASD 操作       │  ← 操作区
└──────────────────────────────────────────┘
```

- 窗口固定 560×720（含标题区与操作区），棋盘区域 480×480，格子间距 12 px，圆角 8 px。
- 窗口不可拉伸；在高 DPI 屏幕上按系统缩放正常显示。
- 主菜单、设置、排行榜、昵称输入为整屏页面，沿用同一套配色与圆角风格；全屏时画布等比缩放居中。

## 6. 验收标准

以下每项均可直接验证，全部通过方可交付：

1. 干净 Windows 机器双击 `2048.exe` 能在 3 秒内打开窗口，无命令行黑窗、无报错弹窗。
2. 新局开局棋盘上恰有 2 个方块，数值为 2 或 4。
3. `[2,2,2,2]` 向左合并为 `[4,4,0,0]` 且得分 +8；`[4,4,8,0]` 向左为 `[8,8,0,0]` 且得分 +8。
4. 无效方向键（如全部方块已在左侧时按 ←）不新增方块、不加分。
5. 每次有效移动后，棋盘方块总数满足「移动前数量 − 合并次数 + 1」。
6. 出现 2048 方块时弹通关提示，选择继续后可继续操作。
7. 棋盘填满且四个方向都无法合并时，1 帧内出现结束提示。
8. 关闭程序再打开，最高分、显示设置与排行榜记录与关闭前一致。
9. 手动破坏 `save.json`（写入乱码）后启动，程序正常运行且最高分显示 0。
10. 在无 Python 的机器上运行 exe，字体正常显示中文，无方块乱码。
11. 任务管理器中：空闲时 CPU 占用稳定在低位，连续运行 30 分钟无卡顿。
12. exe 属性面板显示自定义图标与版本号信息。
13. 主菜单四个入口均可用；设置切换窗口/全屏即时生效并持久化；排行榜显示前 10 名与登记日期。

## 7. 需求边界（明确不做）

- 不做联网对战、云存档、在线排行榜（排行榜仅本机保存前 10 名）。
- 不做触屏手势（仅键盘 + 鼠标点击按钮）。
- 不做多语言切换（首版中文；代码层可预留，但不实现 UI）。
- 不做自适应窗口缩放与自定义棋盘尺寸（固定 4×4）。
- 不做 AI 自动挂机、作弊模式。
- 不做安装包（Inno Setup / MSI），仅提供绿色单文件 exe；如需，另行立项。

## 8. 约束与假设

- 假设目标机器为 64 位 Windows，屏幕缩放 100%～150% 均正常。
- 假设玩家使用标准键盘，方向键可用。
- PyInstaller 打包需在 **Windows 本机**执行，不支持跨平台交叉编译生成 Windows exe。
- pygame 版本固定为 2.5.x 或 2.6.x，避免与 PyInstaller 钩子不兼容的旧版本。
